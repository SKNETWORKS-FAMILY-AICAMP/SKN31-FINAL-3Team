# 구매 진행 현황 개선 (2026-09-28)

## 개요

팀원의 `front개선사항.txt`를 검토하여, 구매 실행 로직은 유지하고 관측·표시 경로를 개선했다.

- 기존 1.8초 전체 목록 폴링 제거. SSE 진행 신호 + 30초 경량 조회로 대체.
- 대시보드 구매 건 상세에서 담당자/관리자만 AI 판단 기록을 조회.
- 마감 작업이 저장한 실제 대기 사유·점검 시각·소요 시간·ERP 호출 수 표시.
- 처리 상태/실행 대기 건수와 마지막 확인 시각 표시. 모노크롬 유지, 점검 필요만 저채도 경고색.
- `.env`, 메일 발송 정책, 자동 진행 조건, ERP 데이터 및 DB 스키마는 변경하지 않음.

## 데이터 흐름

1. `cases.transition_case`, `case_logging`, `deadline_jobs.finish`가 기존 연결에서 `pg_notify`를 발행한다.
2. 기존 `/api/procurement/events` SSE가 `event: progress`로 전달한다. 알림함에는 적재하지 않고 토스트도 발생시키지 않는다.
3. 프론트 `useWorkProgress`는 여러 신호를 750ms로 모아 `/api/procurement/progress`를 조회한다. 요청은 한 번에 하나만 실행한다.
4. 구매 건 ID/version/updated_at이 달라졌을 때만 기존 전체 목록 API를 다시 읽는다. 내부 단계 이력만 바뀐 경우 전체 목록 조회는 하지 않는다.
5. 접속 복구/화면 복귀 및 30초 주기에는 같은 경량 조회로 누락을 복구한다. 숨겨진 탭은 주기 조회를 하지 않는다.
6. 판단 기록은 사용자가 펼쳤을 때만 `/cases/{case_id}/decisions`를 30개씩 조회한다. 모델/ERP를 다시 호출하지 않는다.

## 안전·충돌 회피

- 진행 조회: 한 연결, 한 SELECT, 최대 200건(201번째로 잘림 감지), statement_timeout 2초. ERP·RunPod·그래프 잠금 접근 없음.
- 진행 신호: 기존 연결 재사용, 별도 advisory lock/알림함 쓰기 없음. savepoint로 선택적 관측 실패를 업무 트랜잭션에서 격리.
- 수신자: 담당자 및 기존 구매 건 접근 규칙의 관리자. 신호에는 실제 MR/판단 내용이 없고 후속 API가 담당자 조건을 재적용한다.
- AI 기록: 기존 전사 관리자 로그는 그대로 두고, 담당 건만 조회하는 별도 엔드포인트 추가. 전사 권한을 일반 사용자에게 열지 않는다.
- 이전 RFQ/이전 단계의 마감 사유는 PO 등 이후 단계에 표시하지 않는다.
- UNCERTAIN/BLOCKED는 점검 필요로 표시하며 자동 재실행하지 않는다.
- SSE는 부하와 가시성 개선이지, 잠금 교착 자체의 해결책이 아니다. 이전 잠금 수정은 유지한다.

## 의도적으로 구분한 사항 / 남은 확장

- “구매 건 최근 갱신 후”는 DB 갱신 시각 기준이다. 실제 모델 실행 시간이라고 부르지 않는다.
- 처리 상태 건수는 조회된 구매 건의 DB 상태다. 실제 워커 수/큐 깊이/서버 전체 통계라고 부르지 않는다.
- 노드 기록 완료 시 진행 신호를 보낸다. 현재 실행 중 노드를 시작/끝 이벤트로 추적하는 별도 계측은 아직 추가하지 않았다.
- 최근 활동은 기존 실제 알림으로 유지한다. 우측 피드를 새로 중복 배치하지 않는다.
- 캐시 행 개수만으로 규격 평가 “3/5 완료”를 계산하지 않는다. 현재 RFQ·견적 수정본/input_hash에 맞는 분모/분자 계약이 필요하다.
- “오늘 완료/평균 38초” 등은 실행 이력 집계 정의를 만든 뒤 추가한다. 관측된 값만 표시한다.
- 모든 처리가 끝나면 무조건 다음 단계로 간다고 안내하지 않는다. 회사 정책/수동 승인/추가 평가 조건이 남아 있을 수 있다.

## 검증

- `tests/test_work_progress.py`: 담당자 권한, 조회 상한, SQL 구조, 신호 실패 격리, SSE 수신자 분리/연결 정리.
- 프론트 `workProgress.test.mjs`: 과거 단계 사유 차단, 시간 표시, 대기/점검 구분.
- 프론트 `workProgressRefresh.test.mjs`: 이벤트 폭주 병합, 동일 버전 재조회 방지, 실패 재시도, 숨겨진 탭 중지.
- 기존 그래프/마감 스케줄러/대시보드/표 크기/규격 관련 회귀 테스트와 프론트 빌드·린트.
- `tests/dashboard-preview.html`: 운영 API를 호출하지 않는 모의 화면에서 펼침/타임라인 표시 확인.
- 서버 내부의 실제 DB 읽기 전용 검증: 33건, 잘림 없음, 약 32ms (단일 측정, 부하 테스트 수치 아님).

## 롤백
