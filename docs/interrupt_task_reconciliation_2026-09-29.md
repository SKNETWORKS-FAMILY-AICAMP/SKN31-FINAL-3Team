# 최종 협력사 선정 후 인터럽트 불일치 수정

## 쉽게 보는 원인

대상은 `MAT-MR-2026-00178`입니다. 화면은 **견적 수집/최종 선정 대기**였지만,
실제 실행은 이미 **선정 → 발주 진행 → PR 발송**까지 이동해 있었습니다.
PR 수신 주소가 이메일 화이트리스트에 없어 발송이 차단되었습니다.
메일 안전장치는 정상 동작했지만, 실패 처리에서 옛 작업을 다시 PENDING으로
풀고 현재 실행 위치를 화면용 DB에 반영하지 않은 것이 문제였습니다.

그 결과 사용자가 이미 끝난 선정 버튼을 다시 누르면 실제 그래프에는 해당
인터럽트가 없으므로 409 오류가 반복됐습니다. 마감 자동진행도 같은 오류를 만났습니다.

## 확인한 근거

- 서버 배포 기준: `fbebc1d`.
- PostgreSQL: `WAITING_INPUT / QUOTATION_COLLECTION`, `check_quotations` 작업 PENDING.
- PostgreSQL에 저장된 과거 스냅샷: `awaiting_quotation_check`.
- 실제 SQLite 체크포인트: `creating_pr`, 다음 노드 `create_pr`.
- 실제 노드 오류: `PR 수신 이메일이 EMAIL_RECIPIENT_ALLOWLIST에 없어 발송을 차단했습니다.`
- 당시 재개 입력은 `finalize`, 협력사/견적 선택 및 `start_order=True`였습니다.
- 로그에 해당 작업 응답 API의 409 및 마감 자동진행의 동일 예외가 존재합니다.

이는 메일 발송에 성공했다는 뜻이 아닙니다. 이번 조사로 확인한 것은 해당 PR
발송 시도가 화이트리스트 검사에서 차단되었다는 사실입니다.

## 변경 내용

### `backend_logic2/services/workflow_service.py`

1. 동기 응답 및 이어지는 최종 선정 응답이 실패하면 정확한 작업 버전의 잠금을
   해제한 후, 최신 체크포인트로 화면용 DB와 대기 작업을 재투영합니다.
2. 비동기 견적 분석/자동진행 실패에서도 시작할 때의 단계로 되돌리지 않습니다.
3. 오래된 버튼을 누르면 실제 상태를 동기화하되 그 응답은 실행하지 않습니다.
   새로고침 후 현재 단계와 오류를 확인하도록 안내합니다.
4. PR 복원 경로가 이미 진행된 체크포인트를 삭제하지 못하도록 제한했습니다.
   기존 복원은 로컬 체크포인트가 비어 있을 때만 적용합니다.
5. 동기화 자체가 실패해도 원래 오류를 다른 오류로 덮지 않습니다.

### `backend_logic2/services/case_recovery.py`

- 실제 실패는 `values.error`뿐 아니라 LangGraph `tasks[].error`에 저장됩니다.
  이 값을 읽어 화이트리스트 차단 등 원래 원인을 보존합니다.
- 인터럽트를 소비한 뒤 다음 노드가 실패했다면, 이전 대기 작업을 SUPERSEDED로
  정리하고 `FAILED / HUMAN_REVIEW`로 표시합니다. 최신 `workflow_snapshot.next`
  및 `values.status`에는 실제 실패 노드가 남아 있습니다.
- 실제로 사람 답변을 기다리는 인터럽트가 남아 있으면 그 대기를 유지합니다.
- 로컬 체크포인트가 없거나 case/MR 식별자가 다르면 공유 DB를 덮어쓰지 않습니다.
- 기존 주기 동기화가 노드 오류가 있는 잘못된 WAITING_INPUT도 복구합니다.
  실행 중간 상태와 혼동하지 않도록 그래프 실행 잠금이 바쁘면 건너뜁니다.
- 그래프 재개·체크포인트 삭제·메일 재발송·화이트리스트 추가를 하지 않습니다.

## 검증

실제 LangGraph + InMemorySaver로 사람이 대답한 뒤 PR 노드가 실패하는 흐름을
재현했습니다. 저장소는 메모리 모형이며 실제 PostgreSQL 연결은 테스트에서
실패하도록 막았습니다. ERP·SMTP·RunPod는 호출하지 않았습니다.

- 새 회귀 테스트 13개: 동기/비동기 실패, 인접 인터럽트 연속 응답 실패,
  오래된 버튼, 주기 복구, 실행 전 실패, 체크포인트 없음/식별자 불일치,
  종료 건 보존, PR 체크포인트 삭제 방지, 복구 실패, 그래프 잠금 경합.
- 관련 테스트: **44 passed**.
- 전체 테스트: **726 passed, 27 skipped, 4 subtests passed**.
- 건너뛴 테스트는 이번 검증 성공에 포함하지 않습니다.
- `git diff --check` 통과.

## 운영 적용 시 주의

화이트리스트와 TEST_MODE는 변경하지 않습니다. 수신 주소가 여전히 허용되지
않았다면 **재시도해도 발송은 다시 차단되는 것이 맞습니다**. 권한 있는 담당자가
실제 발송 대상과 회사 정책을 확인한 후 별도로 허용 여부를 결정해야 합니다.

정상 상태 동기화와 구매 업무 완료는 다릅니다. 이번 복구는 완료되지 않은 PR을
완료로 표시하거나, 협력사를 다시 선정하거나, 메일을 자동 재발송하지 않습니다.
전체 DB/체크포인트 공유 저장소 전환은 이번 변경 범위가 아닙니다.
