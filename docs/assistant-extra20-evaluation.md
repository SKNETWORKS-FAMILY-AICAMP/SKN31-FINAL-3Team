## 결론

20개 시나리오를 각각 두 번 실행했습니다. **13종 통과, 6종 기능 결함, 1종 읽기 전용 안내 보완**입니다. 같은 시나리오의 모든 발화가 기대값을 충족해야 통과로 판정했습니다.

- 엄격한 기대값 기준: 40회 시나리오 실행 중 26회 통과. 평가 대상 66개 응답 중 51개 통과.
- 잘못된 테스트 판정을 바로잡기 위해 2종을 각각 두 번 추가 실행했습니다. 실제 총 실행은 44회 시나리오, 70개 응답입니다. 이 재검사를 별개의 새 시나리오로 세지 않았습니다.
- 작은 합성 데이터셋을 의도적으로 어려운 질문으로 검사한 결과입니다. 위 비율을 실제 사용자 전체의 정확도나 운영 장애율로 해석하면 안 됩니다.
- 이전 30개 질문의 통과 결과만으로 연속 대화까지 안정적이라고 판단하기에는 검증 범위가 부족했습니다. 이번에는 조건 교체·부정·복합 조건을 넣어 그 한계를 확인했습니다.

현재 서비스·LangGraph·조회 어댑터를 그대로 불러오고, 저장소 조회만 합성 구매 건 20개로 대체했습니다. 모델이 필요한 경로는 기존 설정의 실제 모델 API를 호출하고, 결정적 규칙 경로는 실제 서비스 규칙으로 처리했습니다. API 입력은 고정된 시험 질문과 공개 기능 안내입니다.

- 로그인 역할 조회도 합성 결과로 대체했습니다. 구매 데이터를 읽는 저장소 함수는 테스트 함수로 교체했습니다.
- 신규 운영 세션을 만들거나 구매 상태를 바꾸지 않았습니다.

- 프론트 클릭·스크롤·실제 로그인 세션의 E2E 재검증은 이번 추가 검증에 포함하지 않았습니다.
- 두 번 반복은 재현 여부 확인용이며 모델 응답의 통계적 안정성을 입증하지 않습니다.

## 발견한 문제와 원인

### E10 — PO 결재 질문에 다른 결정 대기 업무가 섞임

질문: “내가 결재해야 할 PO 몇 건이야?”

기대 1건인데 두 번 모두 4건을 반환했습니다. PO 승인 외에 MR 검토와 RFQ 대상 선택까지 포함했습니다.

`query_routing.py::decision_question`이 “내가 … 해야 할”을 일반 결정 업무로 인식하고, `service.py::_plan_node`가 `waiting_for=decision`으로 강제하면서 명시적인 PO 범위가 사라집니다.

제안: 명시된 문서 종류와 결재 단계를 포괄적인 “내 할 일”보다 우선 적용해야 합니다.

### E14 — 첨부 조건과 납기 조건을 동시에 주면 첨부 조건이 사라짐

질문: “무선 마우스 중 첨부파일 있고 3일 이내 납기인 작업은 몇 개야?”

기대 1건인데 두 번 모두 2건을 반환했습니다. 최종 필터는 납기 3일만 있고 `has_attachments=null`이었습니다.

`service.py::_plan_node`의 납기 보정 분기는 필터 전체를 휴리스틱 필터로 교체합니다. 이 때문에 별도로 해석된 첨부 조건을 보존하지 못합니다.

제안: 특정 조건을 보정할 때 전체 필터를 교체하지 말고 해당 필드만 갱신해야 합니다.

### E13 — 완료만 조회 / 완료 제외의 의미가 안정적으로 반영되지 않음

첫 질문: “완료된 무선 마우스 구매 몇 건이야?”

- 1회차: 기대 1건 → 실제 6건. 완료를 “포함”하는 것과 완료“만” 조회하는 것이 혼동됐습니다.
- 2회차: 첫 질문은 정답 1건을 반환했습니다.

후속 질문: “이번에는 완료된 건 빼고 진행 중인 같은 품목만 세어줘”

두 번 모두 기대 5건 대신 6건을 반환했습니다. 최종 `include_closed=true`가 남았습니다.

`service.py`와 `graph.py`의 문맥 필터 병합은 `exclude_defaults=True`를 사용하므로 기본값인 false/None으로 이전 조건을 되돌릴 때 손실 위험이 있습니다. 완료 단어만으로 양의 조건을 적용하는 휴리스틱도 있어 부정문 처리와 함께 수정해야 합니다. 원시 모델 계획은 이번 로그에 없으므로 모델의 최초 출력까지 확정한 것은 아닙니다.

제안: “완료만 / 완료 포함 / 완료 제외”를 구분하고, 조건의 설정·해제·유지를 명시적으로 표현해야 합니다.

### E20 — ‘내가 결정할 일’에 내 권한으로 승인할 수 없는 PO가 포함됨

질문: “외부를 기다리는 건 말고 같은 품목 중 내가 결정해야 할 것만 세어줘”

기대 2건인데 두 번 모두 3건을 반환했습니다. 현재 합성 사용자는 PO 결재권한이 없지만, 배정된 PO 승인 대기 건이 포함됐습니다.

`query_routing.py::personal_scope`는 부정된 “외부”라는 단어도 감지해 `actionable` 대신 `assigned`를 반환합니다.

다른 사람 데이터 유출이나 실제 승인 우회가 발생한 것은 아닙니다. 본인에게 배정되어 볼 수 있는 건을 “내가 실행할 수 있는 일”로 잘못 분류한 문제입니다.

제안: 조회 가능 범위와 실행 가능 업무를 구분하고, 부정된 이전 조건이 현재 업무 범위를 덮어쓰지 않도록 해야 합니다.

### E01 — ‘세어줘’를 총건수 요청으로 처리하지 않음

5개 목록을 조회한 뒤 “그중 외부 응답 기다리는 것만 세어줘”라고 했습니다.

일치하는 두 건 자체는 올바르게 표시했지만, 두 번 모두 `count_requested=false`, `total_count=null`이었습니다. “총건수”가 아니라 현재 페이지의 표시 건수를 안내한 것입니다.

`query_routing.py::asks_for_count`에 “세어줘”가 없고, 해당 후속 질문은 모델을 생략하는 규칙 경로로 처리됩니다.

이번 2건 예시에서 잘못된 숫자를 말한 것은 아닙니다. 그러나 결과가 한 페이지를 넘는 경우 총건수를 답한다는 요구를 충족하지 못할 수 있습니다. 그 대용량 영향은 이번 E01에서 직접 재현하지 않았습니다.

### E06 — 존재하지 않는 순번을 다시 물어보지 않음

5개 결과 뒤 “여덟 번째 건 알려줘”를 물으면, 두 번 모두 어느 건인지 확인하지 않고 기존 5개 목록을 반복했습니다.

`graph.py::resolve_context`의 한글 순번 처리는 첫·두·세·네·다섯까지만 직접 지원합니다.

제안: 한글 순번을 확장하고, 목록 범위를 벗어나면 명확히 되물어야 합니다.

### E16 — 실행 요구에 읽기 전용임을 명시하지 않음 (안내 보완)

“MAT-MR-2099-00007 승인해줘”에 실제 승인은 수행하지 않았습니다. 현재 단계·승인 역할 설명과 올바른 PO 바로가기를 반환했습니다.

다만 “저는 직접 승인하지 않습니다”라는 설명이 없어 실행을 요청한 사용자에게 처리 여부가 불명확할 수 있습니다. 기능 수행 실패나 승인 권한 침해로 분류하지 않고 안내 보완으로 구분했습니다.

`service.py::_heuristic_plan`과 `_plan_node`는 MR 번호를 실행 요구 검사보다 우선하여 상태 조회로 처리합니다.

제안: 상태를 읽고 올바른 화면으로 안내하되, 직접 실행하지 않았음을 함께 알려야 합니다.

## 테스트 판정 자체의 수정 이력

E11 최초 검사에서 “없습니다”라는 단어를 모두 금지해, 정상 문장인 “현재 구매 작업 저장소에 연결할 수 없습니다”도 실패로 분류했습니다. 이는 챗봇 결함이 아니라 테스트 결함입니다. 빈 결과라고 단정하는 표현만 금지하고 연결 장애 안내를 요구하도록 수정한 뒤 두 번 재검사했으며 모두 통과했습니다.

E16 최초 검사는 안내 intent 및 조회 미실행만 허용했습니다. 그러나 올바른 화면을 찾기 위해 해당 MR의 상태를 읽는 것은 적절합니다. 따라서 조회 자체는 허용하고 ‘직접 승인하지 않음’의 설명을 검사하는 방식으로 바꿨습니다. 재검사에서도 설명 누락은 남았습니다.

최초 결과를 덮어쓰지 않고 보존했으며, 최종 집계에는 두 시나리오의 재검사 결과를 사용했습니다.

## 후속 수정 및 배포 전 재검증 — 2026-10-06

사용자의 수정·배포 승인 후, 구매 그래프가 아닌 `backend_logic2/assistant`의 조회·문맥 처리만 변경했습니다.

- 필터 병합을 `query_constraints.py`로 모으고, 납기/대기 보정 시 다른 조건을 보존합니다.
- 최종 병합 뒤 명시된 조건을 필드 단위로 적용합니다. 완료만/완료 포함/완료 제외와 첨부 있음/없음을 구분합니다.
- PO 결재는 포괄적인 결정 대기보다 우선하며, 부정된 이전 절의 ‘외부’가 내 실행 가능 범위를 덮어쓰지 않습니다.
- ‘세어줘’·‘집계’도 전체 건수 요청으로 처리하고, 한글 순번을 열두 번째까지 해석하여 범위 밖이면 재질문합니다. 화면에 표시되는 최대 10건을 넘는 순번은 범위 밖입니다.
- MR 번호가 있는 실행 요청도 직접 실행하지 않았다는 읽기 전용 안내를 제공합니다.
- 반복 모델 검사에서 추가로 발견한 ‘마우스 말고 키보드’를 ‘무선 키보드’로 추측하는 현상을 방어합니다. 명시적으로 바꾼 품목명 전체를 사용합니다.
- 기존 이어보기/일반 승인 대기/실패 작업 조회를 유지하며, 지원하지 않는 조건 정보가 문맥 병합 중 유실되지 않도록 했습니다.
