# 챗봇 의미 기반 라우팅 · 8턴 기억

## 바꾼 이유

`내 승인을 기다리는 작업이 몇 개야?`를 정식 MR/PO 승인으로만 좁혀
조회하면서 사용자가 뜻한 `내가 결정할 작업`을 놓쳤다. 조회 SQL 검증과
사용자 의도 검증은 다르므로, 모호성 확인·후속 질문·권한별 결과를 따로 검증한다.

## 실행 흐름

현재 구조도: [PNG](diagrams/assistant-semantic-graph.png), [SVG](diagrams/assistant-semantic-graph.svg).
이전 `assistant-readonly-graph`는 첫 버전의 구조도이며 현재 분기는 위 파일을 기준으로 한다.

1. `graph.resolve_context`: 확실한 MR 지칭·확인 질문 선택지를 해석한다.
2. `service._plan_node`: 최근 기억과 전체 27개 화면 기능의 목적을 함께
   제공하여 등록된 capability와 feature_id를 고른다. 낮은 확신이면 조회 전 되묻는다.
3. `authorized_read` 또는 `guide_lookup`: 구매 조회와 화면 안내 분기를 분리한다.
4. `grounded_response`: 구매 숫자와 상태는 조회 결과로 구성한다. 모델이
   실제 구매 데이터를 다시 서술하거나 임의 건수를 만들지 않는다.
5. `remember_context`: 최근 8개의 질문·해석 결과를 남기고 이전 의도를 압축한다.

기능 레지스트리: `capabilities.py`. 검색·건수·상세·내 업무·기능 안내·사용법·
확인 질문·미지원의 8종류다. 화면 feature_id는 실제 사전에 있는 ID만 허용한다.
프롬프트가 역할·SQL·화면 URL을 자유롭게 생성하지 못한다.

## 내 업무의 의미와 권한

- visible: 기존 로그인 사용자의 조회 가능 범위.
- assigned: 관리자라도 현재 계정에 배정된 건만.
- actionable: 기존 조회 범위 안에서 담당자 결정/확인이 필요한 상태.
  외부 답변만 기다리는 건은 제외한다. 자동 진행 조건 미달도 포함한다.
- PO 승인/재처리는 `adapters/user_access.py`에서 기존 `read_policy_access`와
  `can_approve_po`를 읽기 전용으로 호출한다. 조회당 최대 한 번이며 실패 시
  0건이라고 답하지 않는다. 관리자라는 이유만으로 PO 승인 권한을 부여하지 않는다.

‘내 승인’이 모호하면 정식 결재만 / 결정 업무 전체를 선택하게 한다.
선택 후에는 원 질문의 집계 의도와 필터를 유지한다. 기존 구매 API와 역할 판정은 수정하지 않는다.

## 기억과 개인정보 경계

- 1턴은 질문과 응답 한 쌍이다. 최근 8턴의 사용자 질문과 **의미 구조**를 유지한다.
- 모델에는 구매 카드·가격·상태를 포함한 답변 원문을 재전송하지 않는다.
  응답의 의미 구조(선택 기능, 필터, 사용법 주제, 확인 질문)만 전달한다.
- 9번째 이후 오래된 해석은 로컬에서 증분 압축한다. 최대 8개 요약 항목,
  합계 3,000자이며 같은 의미의 중복 항목은 합친다. 추가 LLM 요약 호출은 없다.
- 요약은 과거 검색 의도이지 최신 사실이 아니다. 권한·건수·상태는 재조회한다.
- `assistant_session.dialogue`의 JSONB를 재사용한다. 새 마이그레이션·구매
  체크포인트·스케줄러는 없다. 기존 화면 대화 보관 한도(최근 80메시지/512KB)는
  별개이며, 기억 압축 때문에 대화 원문을 8턴으로 삭제하지 않는다.
- 예전 세션은 마지막 8턴의 질문·응답 메타데이터로 안전하게 복원한다.
  예전부터 저장되지 않았던 의미나 삭제된 원문을 복원했다고 주장하지 않는다.
- 세션 소유자 검사, optimistic version 검사, 삭제 후 늦은 응답 저장 차단은 유지한다.

## 검증과 제한

2026-10-06 로컬 검증 결과:

- 전체 회귀 테스트: 1,009개 통과, 27개 건너뜀, subtest 45개 통과.
  건너뛴 항목은 검증 완료로 계산하지 않는다.
- 실제 설정 모델 + 가상 구매 데이터의 자연어 시나리오: 30/30 통과.
  모호한 승인 → 선택 → 건수 후속 질문, 표현 변형, 조건 제거, 기능 위치 안내,
  미지원 조건 확인, 8턴 초과 후 이전 품목 검색 복원을 포함한다.
  추가 13종은 특정 MR, 견적 회신 건수, 내 담당 건수, 첨부 여부, 3일 이내 납기,
  완료 건, PO 승인 권한, 마감 연장, 건별 자동화 중지, 허용 주소 추가, 거래 평가,
  발송 요청의 읽기 전용 안내, 대체품 결정 위치다.
  첨부·납기는 일치하는 가상 MR을 실제로 반환하는 것까지 검증한다.
- 실제 운영 사용자 데이터의 정확도나 운영 배포 후 검증을 대신하는 결과는 아니다.
  배포 이후에는 별도의 운영 환경 재검증이 필요하다.

`tests/test_assistant_semantic.py`: 모호한 승인, 선택지, 후속 질문, 담당/승인권한,
외부 대기 제외, 9턴 압축, 세션 복원, 위조 문맥, 미지원 요청, 허구 기능 ID.

`tools/assistant_semantic_eval.py --env-file <path> --output <json>`:
실제 모델을 사용하는 별도 평가. 고정 질문과 **가상 구매 데이터**만 사용하며
실제 DB/ERP 조회는 대체한다. 키를 출력하지 않고 일반 pytest/CI에서는 실행하지 않는다.

모든 자연어 표현의 정답을 보장하지 않는다. 새로운 표현·모호성 사례는 실제
기대 의미를 기준으로 회귀 평가에 추가해야 한다. 조회는 최대 2,000건 범위이며
초과 시 범위를 좁히도록 한다. 최근 전체 대화를 무제한 프롬프트로 보내지 않는다.

모델/기본 추론 설정은 기존 GPT-5.6 Luna / medium을 유지한다.
