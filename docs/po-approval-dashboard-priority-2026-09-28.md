# PO 승인 권한 및 대시보드 우선순위 (2026-09-28)

## 변경 개요

- 협력사 선정 표 상단의 긴 안내 컨테이너를 제거했다.
- PO 정렬·검색·레이아웃 초기화를 같은 도구줄에 배치하고 숨김 라벨 스타일을 보완했다.
- PO 최종 승인과 실패 후 재시도는 ERPNext의 `Purchase Manager` 또는 `Purchase Master Manager` 역할이 있는 활성 사용자만 허용한다.
- 대시보드는 상태별 색상 대신 긴급도 정렬과 행 왼쪽 4px 표시를 사용한다. 카드 배경은 흰색으로 유지한다.

## 권한 적용 위치

백엔드 `backend_logic2/policies/access.py`의 `can_approve_po()`가 활성 여부와 실제 ERP 역할을 판정한다. 기존 회사 정책 관리 권한과 별개이며, Administrator/System Manager라는 이유로 PO 승인 권한을 추가하지 않는다. ERP 역할이나 사용자 설정을 생성·변경하지 않는다.

`backend_logic2/api/procurement_routes.py`에서 기존 구매 건 접근 권한을 확인한 뒤, `po_approval`과 `po_creation_failed` 응답 전에 ERP 역할을 다시 조회한다. 발주 단계의 실패 체크포인트를 `/cases/{id}/start`로 재실행하는 경로도 검사한다. 권한 없음은 403, ERP 조회 불가는 503이며 그래프를 재개하거나 작업 상태를 변경하지 않는다. 기존 버전 충돌·담당자 범위 검사는 유지한다.

프론트는 `/api/company-policy/capabilities`의 `can_approve_po`를 사용한다. 조회 전/실패 시 비활성화하고 창 포커스 시 갱신한다. PO 생성·최종 승인·실패 재처리 UI를 제한하며, 열린 화면의 오래된 권한을 조작해도 최종 판단은 서버가 담당한다.

## 대시보드 정렬 및 시간 기준

1. **막힘·점검 필요**: 오류, FAILED, HUMAN_REVIEW, PR_REJECTED, 현재 단계·상태가 일치하는 자동 진행 BLOCKED/UNCERTAIN 기록. RUNNING/QUEUED가 60분 이상 갱신되지 않은 경우도 점검 대상으로 표시한다.
2. **오늘 안에·기한 경과**: 한국 시간 기준 오늘 또는 이전 납기/현재 견적 마감.
3. **나머지**: 결정 대기 / 시스템 처리 중 / 외부 응답 대기 / 기타. 일반 승인은 회색이며 무조건 긴급으로 표시하지 않는다.

각 그룹 안에서는 가장 이른 기한, 동일하면 MR 번호순으로 정렬한다. 긴급 그룹으로 이동한 행은 다른 그룹에 중복 표시하지 않는다. 더보기의 기본 정렬도 동일하며 사용자가 MR 번호순·납기순으로 변경할 수 있다.

행에는 `납기 D-2`, `견적 마감 3시간 남음`, `최근 갱신 후 5시간`을 표시한다. 최근 갱신은 실행 시작 시각이 아니므로 **실제로 5시간 동안 멈췄다고 단정하지 않는다**. 60분 기준은 화면 점검 표시 기준일 뿐 타임아웃·재시도·중단 설정이 아니다. 공급사 응답 및 입고 대기는 오래됐다는 이유만으로 실행 정지로 간주하지 않는다.

납기 없는 건은 기한 미지정이다. 기존 매퍼의 오늘 날짜 기본값을 긴급도 근거로 사용하지 않도록 실제 `requestedDueDate`를 별도 전달한다. 견적 마감은 견적 수집·선정 단계에만 적용하여 이전 RFQ 기한이 PO 단계에 섞이지 않게 한다. 미래/누락된 갱신 시각은 경과 시간 계산에 사용하지 않는다.

상단 네 KPI 대신 오늘의 한 줄과 최우선 작업 바로가기를 배치한다. 행 색과 함께 텍스트·아이콘을 표시하며, 빈 필터 결과와 정상적으로 처리할 일이 없는 상태를 구분한다. 시간 표시는 브라우저에서 분당 갱신하며 API/ERP 폴링을 추가하지 않는다.

## 검증 방법

- 백엔드: `tests/test_po_approval_access.py`, `tests/test_company_policy_access.py` (ERP·DB·그래프 모의 처리).
- 프론트: `node --test tests/*.test.mjs`, `npm run build`, `npm run lint`.
- 브라우저: `tests/ui-layout-preview.html`에서 승인 권한 토글·PO 도구줄·안내 삭제, `tests/dashboard-preview.html`에서 정렬·시간 근거·더보기·바로가기 확인. 모든 서버 호출과 발송은 모의 처리한다.
- 실거래 PO 발송 테스트는 하지 않는다. 기존 `.env`, TEST_MODE, 화이트리스트, 자동 진행 정책은 변경하지 않는다.
