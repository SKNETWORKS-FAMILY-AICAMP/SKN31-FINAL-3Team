# Qwen3.5-9B 견적서 파인튜닝 전후 비교 분석

## 1. 결론

동일한 평가 이미지 100장과 동일한 원본 정답 12종을 기준으로 채점한 결과, 파인튜닝 후 정확도는 **64.42%에서 98.47%로 34.05%p 상승**했다.

| 핵심 지표 | 학습 전 | 파인튜닝 후 | 변화 |
|---|---:|---:|---:|
| JSON 파싱 성공 | 99/100 (99.00%) | 100/100 (100.00%) | +1건 |
| 원본 정답값 정확도 | 632/981 (64.42%) | 966/981 (98.47%) | +34.05%p |
| 오답 수 | 349 | 15 | -334 (-95.70%) |
| 원본 정답값 완전일치 문서 | 11/96 (11.46%) | 84/96 (87.50%) | +73건 |

평가 이미지 중 4장은 추출할 정답값이 없는 `layout_negative` 문서다. 따라서 원본 정답값 완전일치율의 분모는 실제 정답값이 있는 96장으로 계산했다.

학습 전 결과는 `qwen3.5_9b_without-tuning_test_result_with_latency.ipynb`의 저장된 셀 출력에서 문서별 JSON을 다시 추출했다. 학습 후 결과는 `final_a_1476_batch8/document_results.jsonl`의 문서별 예측을 사용했다.

문자열은 모든 공백을 제거한 뒤 정확히 비교했고, 숫자는 숫자형으로 변환해 소수 둘째 자리까지 비교했다. JSON 파싱 실패는 해당 문서에서 채점할 값이 있다면 모두 오답으로 처리한다. 이번 베이스라인 파싱 실패 문서 `aug_000100`은 정답값이 없는 음성 문서이므로 981개 원본 정답값 정확도에는 영향을 주지 않지만, JSON 파싱 성공률에는 실패로 반영된다.

## 4. 전체 JSON 스키마 기준 보조 결과

학습 후 기존 평가기는 정상 문서 96장에 각각 21개 출력 필드를, 음성 문서 4장에 각각 11개 출력 필드를 채점했다.

```text
96 × 21 + 4 × 11 = 2,060
```

같은 규칙을 학습 전 출력에도 적용한 결과는 다음과 같다.

| 전체 스키마 지표 | 학습 전 | 파인튜닝 후 | 변화 |
|---|---:|---:|---:|
| 필드 정확도 | 1,317/2,060 (63.93%) | 2,044/2,060 (99.22%) | +35.30%p |
| 스키마 완전일치 문서 | 1/100 (1.00%) | 88/100 (88.00%) | +87건 |
| 손글씨 필드 정확도 | 755/1,260 (59.92%) | 1,244/1,260 (98.73%) | +38.81%p |
| 컴퓨터 작성 필드 정확도 | 262/420 (62.38%) | 420/420 (100.00%) | +37.62%p |
| 폰트 합성 필드 정확도 | 269/336 (80.06%) | 336/336 (100.00%) | +19.94%p |
| 음성 문서 필드 정확도 | 31/44 (70.45%) | 44/44 (100.00%) | +29.55%p |

전체 스키마 평가는 `business_registration_no`, `valid_until`, `currency`, `notes`, 납기 필드처럼 정답이 `null`인 필드도 “올바르게 `null`을 출력했는지” 채점한다. 또한 하나의 규격 원문을 `description`, `specifications`, `raw_description`에 반복해 평가하고, 공급가액도 `subtotal`과 품목 `amount`에 반복한다. 따라서 이 99.22%는 실제 문서에 존재하는 2,060개의 독립 OCR 값 정확도가 아니다. 출력 계약 준수도를 확인하는 보조 지표로만 해석해야 한다.

## 7. Latency 참고값

| 지표 | 학습 전 | 파인튜닝 후 |
|---|---:|---:|
| 모델 로딩 | 101.81초 | 75.16초 |
| 문서당 평균 생성 | 4.07초 | 2.98초 |

학습 전은 FP16, 학습 후는 BF16이었고 실행 시점의 GPU 캐시와 전처리 상태도 동일하게 통제되지 않았다. 따라서 latency 차이는 파인튜닝 효과로 결론 내리지 않고 참고값으로만 남긴다.

## 8. 한계와 최종 판단

- 100개 `plan_id`는 학습에서 제외됐지만, 원본 양식 28종, template 18종, source sample 66종, 작성자 5종은 학습 데이터와 겹친다.
- 따라서 본 결과는 동일 합성 데이터 생성 체계 안에서의 분포 내 성능이다.
- 평가 정답은 단일 품목 중심의 12개 원본 필드만 제공한다. 다품목 행 누락·행 순서·전체 합계 검증 능력은 이 평가로 확인할 수 없다.
- 베이스라인 노트북과 학습 후 평가의 의도된 JSON 스키마는 같지만, 베이스라인 prompt hash가 별도로 보존되지 않아 프롬프트의 바이트 단위 동일성은 증명할 수 없다.
- 실서비스 배포 판단 전에는 양식·공급사·작성자가 학습 데이터와 겹치지 않는 외부 실문서 테스트셋이 필요하다.

이 한계를 전제로 하면 Final A는 동일 평가셋에서 원본 정답값 오답의 **95.70%를 제거**했으므로 현재 모델 중 배포 후보로 채택할 근거가 충분하다. 다음 우선순위는 추가 epoch가 아니라 독립 실문서 및 다품목 견적서 평가다.
