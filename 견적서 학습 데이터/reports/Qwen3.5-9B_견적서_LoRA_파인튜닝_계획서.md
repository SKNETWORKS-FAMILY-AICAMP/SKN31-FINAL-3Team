# Qwen3.5-9B 견적서 LoRA 파인튜닝 계획서

## 1. 파인튜닝 개요

본 프로젝트에서는 Qwen/Qwen3.5-9B 멀티모달 모델을 기반으로 견적서 이미지에서 필요한 정보를 추출하고, 정해진 JSON 구조로 변환하는 견적서 특화 모델을 개발한다. 학습에는 인쇄 상태가 깔끔한 견적서와 손글씨가 포함된 견적서를 함께 사용하며, RunPod GPU 환경에서 4-bit QLoRA 방식으로 파인튜닝할 예정이다.

전체 모델을 다시 학습하는 대신 LoRA 어댑터만 학습하여 GPU 메모리 사용량과 학습 비용을 줄이고, 기존 모델의 일반적인 이미지·문자 이해 능력을 유지하면서 견적서 도메인에 필요한 기능을 강화한다.

## 2. 파인튜닝 목적

파인튜닝의 최종 목적은 사용자가 업로드한 다양한 형태의 견적서를 사람이 직접 옮겨 적지 않아도 시스템에서 사용할 수 있는 구조화 데이터로 자동 변환하는 것이다.

구체적인 학습 목적은 다음과 같다.

1. **견적서 텍스트 인식 능력 향상**

   - 인쇄된 글자뿐 아니라 사람마다 모양이 다른 손글씨를 인식한다.
   - 숫자, 날짜, 사업자등록번호, 품목 코드처럼 오인식 위험이 큰 값을 정확히 읽는다.
   - 흐림, 기울어짐, 조명 차이, 촬영 이미지 등 실제 입력 환경에 대응한다.
2. **견적서 항목과 JSON 키의 매핑 능력 향상**

   - 문서에서 읽은 값을 `quotation_id`, `supplier_name`, `quotation_date`, `items`, `total_amount` 등 지정된 필드에 올바르게 배치한다.
   - 견적서 양식이나 항목 위치가 달라져도 항목의 의미를 기준으로 값을 매핑한다.
   - 품목이 여러 개인 경우 각 행의 품목명, 수량, 단가, 금액이 서로 섞이지 않도록 추출한다.
3. **일관된 JSON 출력 형식 확보**

   - 설명문이나 Markdown 없이 JSON만 출력하도록 학습한다.
   - JSON 키 이름과 계층 구조를 고정한다.
   - 확인할 수 없는 값은 임의로 생성하지 않고 `null`로 출력한다.
   - 후속 시스템에서 별도의 복잡한 문자열 가공 없이 결과를 사용할 수 있도록 한다.
4. **견적서 도메인 적합성 향상**

   - 일반적인 OCR을 넘어 공급자 정보, 견적일, 유효기간, 공급가액, 세액, 합계 및 품목 표 등 견적서의 업무 구조를 이해하도록 한다.
   - 모델이 이미지에 적힌 값을 그대로 추출하게 하고, 합계 검산이나 숫자 보정 등 업무 규칙은 후처리 단계에서 수행할 수 있도록 원문 추출과 업무 계산을 분리한다.

## 3. 학습 데이터 구성 계획

학습 데이터는 `파인튜닝 데이터` 폴더에 생성된 증강 견적서 6,000건을 사용한다. 전체 데이터는 무작위 생성 계획에 따라 이미 구성이 완료됐으며, 현재 생성된 분포를 그대로 사용한다.

현재 데이터 구성은 다음과 같다.

| 생성 유형 | 건수 | 학습 목적 |
|---|---:|---|
| 사람 필적 합성(`handwriting_composite`) | 3,600 | 손글씨 형태의 문자와 숫자 판독 |
| 폰트 합성(`font_composite`) | 960 | 다양한 글꼴 및 문서 표현 대응 |
| 컴퓨터 기입본(`computer_filled`) | 1,200 | 깔끔한 정형 견적서 처리 능력 유지 |
| 레이아웃 네거티브 샘플(`layout_negative`) | 240 | 잘못된 위치의 값을 추출하거나 임의 값을 생성하는 오류 억제 |

이미지는 1,000건 단위의 `chunk_0001_1000`부터 `chunk_0006_6000`까지 총 6개 청크로 나뉘어 있다. 각 청크에는 `images` 폴더와 해당 청크의 `annotations.jsonl`이 있으며, 최상위 `annotations.jsonl`에는 6,000건의 annotation이 통합돼 있다. `manifest.json`에는 이미지 수, annotation 수, 생성 유형, 노이즈 강도 및 검증 상태가 기록돼 있다.

노이즈 강도는 `cleanish`, `light`, `medium`, `strong`으로 구성돼 있어 깔끔한 이미지와 품질이 저하된 이미지를 함께 학습할 수 있다. 파일럿과 최종 학습에서는 현재 생성된 분포를 그대로 사용한다.

각 데이터에는 다음 정보를 관리한다.

- 견적서 이미지 경로
- 정답 JSON
- 생성 방식(`generation_mode`)
- 양식 식별자(`template_id`)
- 증강 계획 식별자(`plan_id`)
- 증강 전 기준 이미지 식별자(`base_source_id`)
- 배치된 필드와 배치되지 않은 필드
- 노이즈 및 증강 정보

정답 JSON은 모든 데이터에서 동일한 스키마와 키 순서를 사용한다. 이미지에 표시된 값과 계산으로 보정한 값을 혼합하지 않으며, 이미지에서 확인할 수 없는 필드는 `null`로 기록한다.

## 4. 학습 및 검증 데이터 운용

현재 데이터는 여러 생성 유형과 노이즈 조건을 무작위로 조합한 증강 데이터다. 준비된 `모델 평가 데이터/견적서 100`을 내부 검증 데이터로 사용한다.

- 내부 검증용 100건에 해당하는 `plan_id`는 학습 목록에서 제외한다.
- 나머지 약 5,900건을 파일럿 및 최종 LoRA 학습에 사용한다.
- 파일럿 A와 B는 동일한 학습 샘플과 동일한 내부 검증 100건으로 비교한다.
- 내부 검증 데이터는 checkpoint 선택과 과적합 확인에만 사용한다.
- 검증 결과는 실제 신규 문서 전체에 대한 일반화 성능이 아니라, 현재 생성 데이터 분포 안에서의 상대적인 개선 정도로 해석한다.
- 추후 실제 견적서가 추가되면 기존 학습 결과를 변경하지 않고 별도의 실사용 평가를 진행한다.

## 5. 학습 데이터 형식

각 샘플은 견적서 이미지, 추출 지시문, 정답 JSON으로 구성한다.

```json
{
  "messages": [
    {
      "role": "system",
      "content": "견적서 이미지에서 값을 읽어 지정된 JSON 형식으로만 출력한다. 확인할 수 없는 값은 null로 출력한다."
    },
    {
      "role": "user",
      "content": "<image>견적서의 모든 항목을 지정된 JSON 스키마로 추출하세요."
    },
    {
      "role": "assistant",
      "content": "{\"quotation_id\":\"...\",\"supplier_name\":\"...\",\"items\":[...]}"
    }
  ],
  "images": [
    "/workspace/dataset/images/quotation-00001.png"
  ]
}
```

학습과 실제 서비스 추론에서 같은 프롬프트와 JSON 스키마를 사용한다. 모델에는 정답 응답 부분을 중심으로 손실을 적용하여 이미지 및 지시문을 그대로 암기하기보다 올바른 JSON 결과를 생성하도록 학습한다.

## 6. 파인튜닝 방식

학습은 RunPod에서 Qwen3.5-9B 모델을 4-bit로 불러온 뒤 LoRA 어댑터를 학습하는 QLoRA 방식으로 진행한다. 전체 파라미터를 학습하는 방식보다 필요한 VRAM과 비용이 적고, 학습된 어댑터를 기본 모델과 분리하여 관리할 수 있다.

어떤 기능이 개선되는지 구분하기 위해 먼저 소규모 비교 학습을 진행한다.

### 6.1 파일럿 A: 구조화 및 키 매핑 중심

- 언어 모델과 멀티모달 projector를 중심으로 LoRA 적용
- Vision encoder는 동결
- JSON 형식, 키 선택, 품목 배열 구성 및 항목 매핑 능력 개선 여부 확인

### 6.2 파일럿 B: 손글씨 인식 포함

- 파일럿 A의 학습 범위에 Vision encoder 일부를 추가
- 손글씨 문자와 숫자 판독 능력 개선 여부 확인
- 시각부에는 언어부보다 낮은 학습률 적용

두 파일럿은 검증용 100건을 제외한 학습 데이터 중 동일한 800~1,000건과 동일한 내부 검증 데이터를 사용하여 비교한다. 더 적합한 설정을 선정한 뒤 나머지 전체 학습 데이터로 최종 학습한다. 따라서 비교용 LoRA 두 개를 모두 전체 데이터로 장시간 학습할 필요는 없다.

## 7. 초기 학습 설정

| 항목                  | 초기 설정                                         |
| --------------------- | ------------------------------------------------- |
| 기본 모델             | Qwen/Qwen3.5-9B                                   |
| 학습 방식             | 4-bit QLoRA SFT                                   |
| 양자화                | NF4, double quantization                          |
| LoRA rank             | 16 또는 32                                        |
| LoRA alpha            | 32 또는 64                                        |
| LoRA dropout          | 0.05                                              |
| batch size            | GPU당 1                                           |
| gradient accumulation | 8~16                                              |
| 학습 epoch            | 파일럿 1회, 최종 2~3회                            |
| 언어부 학습률         | 약 1e-4                                           |
| 시각부 학습률         | 약 1e-5~5e-5                                      |
| 기타                  | gradient checkpointing, validation 기반 조기 종료 |

위 값은 고정된 최종 설정이 아니라 초기 실험값이다. 파일럿 학습의 loss 변화, 검증 정확도, GPU 메모리 사용량을 확인하여 조정한다.


## 8 전체 진행 순서

1. 견적서 JSON 스키마와 각 필드의 의미를 확정한다.
2. 6,000건의 이미지와 정답 JSON을 자동 검사한다.
3. `manifest.json`의 이미지 수, annotation 수 및 오류 상태를 확인한다.
4. 내부 검증용 100건의 `plan_id`를 학습 목록에서 제외한다.
5. RunPod 환경과 학습 라이브러리 버전을 고정한다.
6. 800~1,000건으로 파일럿 A와 B를 각각 1 epoch 학습한다.
7. 내부 검증 100건으로 문자 인식, JSON 구조 및 키 매핑 성능을 비교한다.
8. 더 적합한 LoRA 범위를 선정한다.
9. 선정된 설정으로 검증용 데이터를 제외한 약 5,900건을 2~3 epoch 학습한다.
10. 검증 성능이 가장 좋은 checkpoint를 선택한다.
11. 기본 모델과 최종 LoRA 모델을 내부 검증 데이터에서 동일한 조건으로 비교한다.
12. LoRA 어댑터와 학습 설정, 프롬프트 버전, 데이터 버전 및 평가 결과를 함께 보관한다.

## 9 이후 검증 계획

파인튜닝 완료 후에는 기본 모델과 LoRA 적용 모델을 준비된 내부 검증 데이터에서 동일한 프롬프트와 생성 설정으로 비교한다. 전체 결과를 우선 비교하고, annotation의 `generation_mode`별 표본 수가 충분한 경우 생성 유형별 결과도 함께 확인한다.

- JSON 파싱 성공률
- 스키마 및 필수 키 준수율
- 필드 단위 정확도
- 중요 필드 정확도
- 문서 전체 완전 일치율
- 품목 행 매핑 정확도
- 존재하지 않는 값 생성 비율
- 손글씨 견적서 성능
- 인쇄 견적서 성능 유지 여부
- 문서당 추론 시간과 GPU 메모리 사용량

정량 평가뿐 아니라 대표 오류 사례를 확인하여 숫자 오인식, 필드 간 값 이동, 품목 행 혼합, 임의 값 생성 등 오류 유형을 정성적으로 분석한다. 이를 통해 단순히 전체 점수가 상승했는지를 보는 데 그치지 않고, 파인튜닝을 통해 실제 견적서 처리에 필요한 기능이 개선되었는지를 판단한다.

## 10.기대 효과

파인튜닝을 통해 서로 다른 견적서 양식에 대한 적응력, 손글씨 판독 능력, 견적 항목의 의미 기반 매핑 능력 및 JSON 출력 안정성이 향상될 것으로 기대한다. 최종적으로는 견적서 입력 업무를 자동화하고, 추출 결과를 기존 백엔드 로직과 직접 연동할 수 있는 도메인 특화 멀티모달 모델을 확보하는 것을 목표로 한다.
